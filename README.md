# Functional Structural Signature Model

## Overview

This repository contains the implementation of the **Functional Structural Signature Model**, including the notebooks, datasets, intermediate databases, analytical outputs, and quality assessment artifacts required to execute the complete processing workflow.

The project is designed to run in **Google Colab**.

---

## Environment

**Execution environment:** Google Colab

The notebooks are intended to be executed directly within Google Colab.

Before running the processing pipeline, make sure that the repository and its directory structure are available in the Colab environment and that the required input datasets have been placed in the appropriate folders.

---

## Directory Structure

The project is organized according to the following structure:

```text
/
├── db/
├── Input file/
├── Output/
├── quality/
└── notebooks / project files
```

### `db/`

Contains the **SQLite databases** generated during the processing workflow.

These databases are intermediate working artifacts used by the notebooks during the different processing and analysis stages.

```text
db/
└── *.db
```

Depending on the execution stage, database files may be created, updated, or regenerated.

---

### `Input file/`

Contains all datasets required or used by the processing pipeline.

The main input dataset is mandatory and must be named:

```text
RAW_BASELINE.csv
```

`RAW_BASELINE` represents the starting dataset used to initialize and execute the processing workflow.

The directory may also contain additional datasets used during the different analysis and processing stages.

Example:

```text
Input file/
├── RAW_BASELINE.csv
├── dataset_01.csv
├── dataset_02.csv
└── ...
```

> **Important:** The `RAW_BASELINE` dataset is mandatory.
> The processing workflow cannot be correctly initialized without it.

---

### `Output/`

Contains the **final datasets and exports** generated by the processing pipeline.

These files represent the consolidated results produced after the different processing, transformation, and analysis stages.

Example:

```text
Output/
├── final_export.csv
├── analysis_results.csv
└── ...
```

Files in this directory should generally be considered generated artifacts rather than source datasets.

---

### `quality/`

Contains the artifacts produced during the **quality assessment and analytical validation** phases.

This directory may include:

* charts and graphical analyses;
* statistical analysis results;
* quality indicators;
* validation results;
* diagnostic outputs;
* intermediate analytical reports.

Example:

```text
quality/
├── charts/
├── analysis_results/
└── ...
```

The content of this directory is intended to support the evaluation and interpretation of the quality of the processing results.

---

## Running the Project

### 1. Open the notebook in Google Colab

Upload or open the project notebook directly from the GitHub repository using Google Colab.

### 2. Prepare the input data

Make sure that the mandatory baseline dataset is available in:

```text
Input file/RAW_BASELINE.csv
```

The file must follow the CSV standard described above.

### 3. Check additional datasets

If additional datasets are required by the analysis, place them in the `Input file/` directory before executing the corresponding processing stages.

### 4. Execute the notebook

Run the notebook cells in the defined execution order.

During execution, the workflow may:

1. load the baseline dataset;
2. validate and normalize input data;
3. generate intermediate processing structures;
4. create or update SQLite databases;
5. perform analytical processing;
6. execute quality and validation analyses;
7. generate final CSV exports;
8. produce charts and analytical results.

### 5. Review generated artifacts

After execution, results can be found in:

```text
db/        → SQLite working databases
Output/    → final processing exports
quality/   → charts, quality analyses and validation results
```

---

## Input Requirements

Before starting the workflow, verify that:

* `RAW_BASELINE.csv` exists;
* the file is located in the `Input file/` directory;
* the CSV uses `;` as field separator;
* decimal values use `,`;
* the file is UTF-8 encoded;
* required columns are available;
* additional datasets required by specific processing stages are present.

## Generated vs. Source Artifacts

The repository distinguishes between **source data** and **generated artifacts**.

**Source data**

```text
Input file/
```

These files provide the data required by the processing workflow.

**Generated working artifacts**

```text
db/
```

These are generated during execution and support intermediate processing.

**Generated final artifacts**

```text
Output/
quality/
```

These directories contain the final exports, analytical results, charts, and quality assessment artifacts produced by the workflow.

---

## Reproducibility

For reproducible executions:

1. start from the same version of `RAW_BASELINE.csv`;
2. use the same additional input datasets;
3. execute the notebook using Google Colab;
4. maintain the expected directory structure;
5. do not manually modify intermediate SQLite databases unless explicitly required;
6. use the standardized CSV configuration throughout the workflow.

This ensures that the processing pipeline operates with consistent input/output conventions and minimizes environment-dependent differences.

## Notes

* `RAW_BASELINE.csv` is the mandatory entry point of the processing pipeline.
* SQLite databases under `db/` are generated during processing.
* Files under `Output/` contain the final exported results.
